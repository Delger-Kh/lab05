## Ажиллуулах

`{{baseUrl}}` нь collection variable (`http://localhost:3000`) тул нэмэлт тохиргоо шаардлагагүй. Windows PowerShell дээр:

```powershell
node server.js        # тусдаа терминалд: Бүртгэлийн API: http://localhost:3000

newman run lab05-collection.json 2>&1 | Tee-Object -FilePath results/newman-pass.txt
$LASTEXITCODE         # 0

newman run lab05-collection-fail.json 2>&1 | Tee-Object -FilePath results/newman-fail.txt
$LASTEXITCODE         # 1

# серверийг Ctrl+C-ээр унтраагаад:
newman run lab05-collection.json 2>&1 | Tee-Object -FilePath results/newman-down.txt
$LASTEXITCODE         # 1
```

## Сонголт ба төлөөлөх утгын хүснэгт

Бие даан тестлэгдэх функц: `POST /registrations` (оролт: `studentID`, `courseID`; систем дэх төлөв: оюутны бичлэг, хичээлийн бичлэг).

| Сонголт | Утгын анги | Төлөөлөх утга | Хүлээгдэх хариу |
|---|---|---|---|
| `studentID`-гийн хүчинтэй байдал | Идэвхтэй | `B231234567`, `status: "active"` | Цааш шалгана |
| | Идэвхгүй | `B231234567`, `status: "inactive"` | `200`, `ERROR_INACTIVE_STUDENT` |
| | Байхгүй | `B000000000` (бүртгээгүй) | `200`, `ERROR_NO_STUDENT` |
| Оюутны үзсэн хичээлүүд (`coursesTaken`) | Урьдач нөхцөлийг хангана | `["CS201"]` | Цааш шалгана |
| | Хангахгүй | `[]` | `200`, `ERROR_PREREQUISITES` |
| `courseID`-гийн хүчинтэй байдал | Байгаа | `CS313` | Цааш шалгана |
| | Байхгүй | `CS999` (бүртгээгүй) | `200`, `ERROR_NO_COURSE` |

Сервер шалгах дараалал: бие → оюутан байгаа эсэх → идэвхтэй эсэх → хичээл байгаа эсэх → урьдач нөхцөл. Хоёр алдаа зэрэг байвал эхнийх нь л буцна (тест 7, 8).

**Боломжгүй хослолууд:** оюутан байхгүй бол түүний төлөв болон үзсэн хичээлүүд гэсэн сонголт утгагүй; хичээл байхгүй бол түүний урьдач нөхцөл утгагүй. Иймд эдгээрийг бүх хослолоор үржүүлээгүй, нэг төлөөлөх тест (2, 4, 7)-өөр хамруулсан.

## Newman-ы үр дүн

| Ажиллагаа | Файл | requests (executed / failed) | assertions (executed / failed) | Exit code |
|---|---|---|---|---|
| Сервер асаалттай, үндсэн collection | `results/newman-pass.txt` | 26 / 0 | 24 / **0** | **0** |
| Сервер асаалттай, fail collection | `results/newman-fail.txt` | 26 / 0 | 24 / **1** | **1** |
| Сервер унтраалттай, үндсэн collection | `results/newman-down.txt` | 26 / **26** | 24 / 24 | **1** |

### Fail collection

`lab05-collection-fail.json`-д 1-р тестийн статусын oracle-ийг `201`-ээс `200` болгож зориуд буруу болгосон. Сервер зөв ажиллаж `201` буцаасан тул Newman `AssertionError: expected response to have status code 200 but got 201` гэж 1 assertion унагаж, exit code 1-ээр дууссан. Энэ нь тест бодит алдааг илрүүлж чадна, мөн CI-д унасан ажиллагаа exit code-оор ялгарна гэдгийг харуулна.

### Сервер унтраалттай — интерфейсийн алдаа ба oracle-ийн алдааны ялгаа

`newman-down.txt`-д хүсэлт бүр `connect ECONNREFUSED 127.0.0.1:3000` гэж унасан (26/26 request failed, exit code 1).

- **Интерфейсийн алдаа** (`newman-down.txt`): сервертэй холбогдож чадаагүй тул хариу огт ирээгүй. Тестийн скриптүүд хоосон хариу дээр ажиллаж `JSONError` / `to have property 'code'` гэж унасан — эдгээр нь API буруу ажилласныг бус, тест ажиллах орчин бэлэн биш байгааг илтгэнэ. Шийдэл нь кодыг засах биш, серверийг асаах.
- **Oracle-ийн алдаа** (`newman-fail.txt`): сервер хариу өгсөн (request failed = 0), харин хүлээгдэж буй утга бодит хариутай таараагүй (`AssertionError`). Энэ нь систем эсвэл тестийн хүлээлт буруу гэсэн үг бөгөөд задлан шинжлэх шаардлагатай.

Хоёулаа exit code 1 өгдөг тул зөвхөн exit code-оор ялгах боломжгүй; `requests failed` мөр болон алдааны төрлийг (`ECONNREFUSED` vs `AssertionError`) харж ялгана.

## Дүгнэлт

Лекц 5-ын тест дизайны 5 алхмыг `POST /registrations` функц дээр хэрэгжүүлж, 10 бие даасан тест, 24 assertion бүхий Postman collection бүтээн Newman-аар автоматаар ажиллуулсан. Таван алхмаас хамгийн их бодол шаардсан нь спецификаци (4-р алхам) байсан: сонголтуудын бүх хослолыг үржүүлбэл тест хэт олон болох тул happy path, алдааны анги бүрд нэг, давхар алдаа, хязгаарын тохиолдлыг сонгож цөөн боловч төлөөлөх чадвартай багц гаргах шаардлагатай байсан. Давхар алдааны тестүүдийг бичихийн тулд серверийн шалгах дарааллыг (оюутан → төлөв → хичээл → урьдач нөхцөл) урьдчилан мэдэх хэрэгтэй болсон. Боломжгүй хослол олон таарсан: байхгүй оюутны төлөв, үзсэн хичээл, мөн байхгүй хичээлийн урьдач нөхцөл гэх мэт утгууд ямар ч утга учиргүй тул тэдгээрийг тусад нь тестлээгүй. Тест бүр өөрийн PUT setup-ыг хийдэг тул дарааллаас хамаардаггүй, `registrationID` хуримтлагддаг тул яг утгыг нь бус тоо эсэхийг л шалгасан. Үндсэн ажиллагаа 24/24 assertion амжилттай, exit code 0; зориуд буруу oracle-тэй fail collection 1 assertion унагаж exit code 1 өгсөн нь oracle-ууд зөрүүг бодитоор илрүүлж чадахыг харуулсан. Сервер унтраалттай үед бүх хүсэлт `ECONNREFUSED`-ээр унасан нь интерфейсийн алдаа бөгөөд хариу ирсэн ч утга нь таараагүй oracle-ийн алдаанаас ялгаатай. Миний тестүүд серверт согог олоогүй — бүх спецификаци хүлээгдэж буй статус, `result` утгатай таарсан. Харин оролтын алдаа `200 + ERROR_*` буцдаг тул зөвхөн статус шалгах нь хангалтгүй, `result` утгыг заавал шалгах ёстой гэдгийг ойлгосон.
